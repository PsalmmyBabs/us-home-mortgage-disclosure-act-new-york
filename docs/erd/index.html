US HMDA Entity Relationship Diagram

One partitioned fact table, eight dimensions, four bridges, a quarantine table and a code reference. Drawn from the foreign keys as they exist in the database, not from a design document.

Why the keys look like this

Three things in the diagram are worth a sentence each. Most keys carry activity_year. A lender's asset size, a tract's median income and an MSA's name all change between years, so a key of lei alone would silently mix vintages. Four relationships are bridges, not columns. HMDA lets a filer record up to five races and five ethnicities for each of two parties, four denial reasons and several underwriting systems, so flattening them into the fact table would break first normal form and overstate multi-race applicants. The fact table has no natural key. The Bureau strips every loan identifier before publication, so the business key is an md5 of the source row plus an occurrence number, which makes it reproducible across rebuilds.
